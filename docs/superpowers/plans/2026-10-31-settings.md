# Settings UI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give Regie a searchable Settings window for all existing preferences, with live updates and safe, recoverable TOML editing.

**Architecture:** A typed settings controller owns the last applied configuration and coordinates a lossless config store, file-change notifications, and main-thread runtime effects. A separate tao window with a bundled WKWebView presents a single searchable settings list; typed messages carry edits and state, while existing workspace and dropdown remain responsible for terminal behavior.

**Tech Stack:** Rust, tao/wry, serde, lossless TOML editing (`toml_edit`), native macOS filesystem notifications, bundled HTML/CSS/JS, Playwright WebKit.

**Spec:** `docs/superpowers/specs/2026-10-31-settings-design.md`.

## Global Constraints

- macOS only is tested; no per-tab themes, font setting, or new preferences.
- All 11 existing keys, defaults, ranges, enum values and unknown-key rejection remain compatible.
- Preserve comments, unrelated keys, legacy fallback and user data; never overwrite invalid or inaccessible canonical config with defaults.
- Keep UI settings, terminal colors and terminal font independent; never restart existing shells to apply settings.
- No runtime network assets; serialize all IPC payloads, reject invalid messages and navigate only to the embedded document.
- TDD per task; run `cargo test --all-targets`, `cargo clippy --all-targets -- -D warnings`, `cargo fmt --check`, and relevant browser tests before each logical commit.
- Follow `AGENTS.md`: thin main, native glue behind `cfg`, no unused scaffolding. Do not edit accepted ADRs.

## Review Focus

- External edits during a UI edit: preserve unrelated changes and detect same-field conflicts (Task 1).
- Malformed, inaccessible, legacy and unknown-key config: never discard content or falsely claim recovery (Tasks 1, 2, 6).
- Hotkey registration, file save or runtime apply failure: keep working state and expose unsaved/unapplied status (Tasks 2, 3).
- Atomic replacement, deletion and recreation of config: observe canonical and legacy paths without permanent event-loop polling (Task 4).
- Window focus, active terminal output and delayed callbacks during live changes: preserve sessions, selection and normal focus-loss behavior (Tasks 3, 5, 6).

## File boundaries

- `src/config.rs`, `src/settings_store.rs`: typed keys, validation, lossless reads and atomic edits.
- `src/settings.rs`, `src/settings_watch.rs`: controller state/effects and change notifications.
- `src/dropdown.rs`, `src/workspace.rs`, `src/terminal_protocol.rs`, `src/terminal_view.rs`, `assets/terminal/regie.js`, `assets/terminal/tabs.js`: apply runtime updates without losing sessions.
- `src/settings_view.rs`, `assets/settings/`, `tests/settings/`: separate window, strict typed IPC and bundled searchable UI; browser tests use the production document.
- `src/app_ui.rs`, `src/main.rs`, `src/lib.rs`: menus, warning, focus and main-thread integration.
- `README.md`, `docs/roadmap.md`, new ADR and `docs/testing/settings.md`: shipped behavior, decision and explicit native acceptance evidence.

### Task 1: Lossless settings store and partial validation

**Files:** Create `src/settings_store.rs`; modify `src/config.rs`, `src/lib.rs`, `Cargo.toml`, `Cargo.lock`.

**Interfaces:** Define `SettingKey` with one variant for each existing field; `SettingValue` holds the corresponding typed scalar; `ConfigSnapshot { path: PathBuf, text: String, fields: Vec<FieldState>, status: ConfigStatus }`; `FieldState { key: SettingKey, value: Option<SettingValue>, error: Option<String> }`; `ConfigStatus::{Valid(Config), Invalid, Malformed(String), Unreadable(String)}`. `SettingsStore::read(&AppPaths) -> ConfigSnapshot`; `SettingsStore::write(&AppPaths, expected: &ConfigSnapshot, changes: &[(SettingKey, SettingValue)]) -> Result<ConfigSnapshot, StoreError>`. `StoreError` distinguishes same-field conflict, malformed, inaccessible and failed write.

- [ ] Write store tests for existing defaults/all 11 keys, wrong types/ranges/unknown keys, partial field recovery, and invalid UTF-8; assert full validation still uses `Config::from_toml_str`.
- [ ] Run `cargo test settings_store::tests`; observe missing implementation fail.
- [ ] Implement typed field mapping and TOML document mutation with `toml_edit`; preserve comments, whitespace and unknown keys. Re-read current contents and compare each edited field to the expected snapshot before mutation. Validate individual edits even if other fields are invalid.
- [ ] Test concurrent unrelated change preserved, same-field conflict, quoted values and comments retained, malformed document untouched, atomic-write failure preserves original, missing config creation, unreadable canonical does not fall back, and legacy source is never modified. Create canonical config from legacy losslessly on first edit only when canonical is genuinely absent.
- [ ] Implement sibling temporary-file writes, flush/sync and rename; only clean up the temporary file created by that operation. Treat external writers as uncoordinated: check again immediately before replacement and report a conflict if bytes changed; document that ordinary filesystem APIs cannot make compare-and-rename atomic against arbitrary external editors.
- [ ] Run targeted tests and global checks; commit `feat: settings - preserve and validate config edits`.

### Task 2: Settings controller and recovery policy

**Files:** Create `src/settings.rs`; modify `src/lib.rs`.

**Interfaces:** `SettingsController::new(snapshot: ConfigSnapshot, active: Config)`, `snapshot(&self) -> &ConfigSnapshot`, `active(&self) -> &Config`, `edit(&mut self, key: SettingKey, value: SettingValue) -> Vec<SettingsEffect>`, `reset_all(&mut self) -> Vec<SettingsEffect>`, `external_change(&mut self, snapshot: ConfigSnapshot) -> Vec<SettingsEffect>`, `finish(&mut self, result: SettingsResult) -> Vec<SettingsEffect>`. Effects are typed `Write`, `Apply`, `ShowWarning`, `ClearWarning`, `ShowError`, `Render`; results carry the matching operation generation to ignore stale callbacks. The main thread performs effects and sends results back.

- [ ] Test valid edit sequence, default reset of one/all keys, failed write, malformed and unreadable startup, parseable field error, unknown key, and editing another valid field while invalid: persist it but keep last active config until whole document validates.
- [ ] Run `cargo test settings::tests`; observe red.
- [ ] Implement controller state with separate disk snapshot, last fully applied config and pending operation generation; startup invalid uses defaults and requests Settings plus warning. Failed reads, saves and application remain visible, and stale completions cannot clear a newer warning.
- [ ] Test external valid and invalid changes, revalidation after repair, interrupted reset, failed runtime application, and distinct saved-versus-active status. Verify reset-all never touches session/layout paths.
- [ ] Run checks; commit `feat: settings - coordinate recovery and persisted state`.

### Task 4: Config file observation

**Files:** Create `src/settings_watch.rs`; modify `src/lib.rs`, `Cargo.toml`, `Cargo.lock` if native notification features are needed.

**Interfaces:** `SettingsWatch::new(paths: AppPaths, wake: impl Fn() + Send + Sync + 'static) -> Result<Self, String>` watches parent directories of both canonical and legacy files; drop stops the watcher. Wakes are coalesced; the controller rereads through Task 1 and owns validation.

- [ ] Test write, atomic rename, delete/recreate, canonical creation over legacy, burst coalescing, and watcher teardown with bounded deadlines and no fixed sleeps.
- [ ] Run `cargo test settings_watch::tests`; observe red.
- [ ] Implement macOS filesystem notifications; watch nearest existing ancestors when config directories do not exist, refresh watches as directories appear, and report watcher setup/failure instead of silently missing edits. No permanent tao polling.
- [ ] Run checks; commit `feat: settings - observe external config changes`.

## Self-review

All approved spec sections map to Tasks 1–7; review-focus cases have explicit owning tests. The separate persisted/applied state accounts for invalid files and runtime failures; exact recovery and focus boundaries are exercised before integration. The plan is one milestone because live application, safe writes and recovery are prerequisites for a truthful Settings UI, rather than independently shippable user features.
